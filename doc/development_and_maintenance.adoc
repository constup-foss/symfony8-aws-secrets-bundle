== Setting up development environment

This library is developed on a dockerized development environment using link:https://projectinit.sh[ProjectInit.sh].
ProjectInit produces default technology-specific files (Docker and docker compose files, PHP Unit configuration. Git
configuration, ...) and is not needed directly for maintenance.

Complete instructions on how to run the provided dockerized environment are available in
link:projectinit/index.adoc[ProjectInit's autogenerated documentation].

If you don't want to use provided dockerized environment, take a look inside link:../Dockerfile[`Dockerfile`] to see how
to set up your own.

== Setting up AWS

[IMPORTANT]
====
**This guide assumes that you are developing locally on a standalone AWS account. If you are using your organization's
account for development purposes, consult your organization's documentation for instructions.**

All instructions in this guide are compatible with AWS free tier and a freshly created AWS account.
====

This guide is a short, direct, bullet-point version of the official documentation for
link:https://docs.aws.amazon.com/sdk-for-php/v3/developer-guide/getting-started_index.html[AWS SDK for PHP Version 3].
It assumes that you only have your own standalone AWS root account created with nothing else set up in it. You are free
to skip steps that you've already covered.

=== AWS Authentication

Starting AWS article: https://docs.aws.amazon.com/sdk-for-php/v3/developer-guide/credentials.html[Authenticating with
AWS using AWS SDK for PHP Version 3].

[NOTE]
====
Note that not all steps listed in the official AWS documentation are necessary to set up a testing environment when
developing this library. For example, using IAM Identity Center is not necessary. The steps listed below are verified to
work during development of this library.
====

=== Generating long-term AccessKeyId and SecretAccessKey for development purposes

Steps:

* Create an IAM user group
** Go to **`IAM > IAM users and groups`** (https://console.aws.amazon.com/iam/home?#/groups) and create a new IAM user
group
** Attach the following permission policies when creating the group:
*** `AWSSecretsManagerClientReadOnlyAccess`
* Create an IAM user and add it to the group created previously
** Go to **`IAM > IAM users`** (https://console.aws.amazon.com/iam/home?#/groups) and create a new user
*** You do not need __Provide user access to the AWS Management Console__ option selected, since your IAM user will only
be accessing AWS services programmatically.
*** Add the user to the previously created group
* Create AWS access key
** Open the IAM user you've just created and click on **Create access key**
*** On the __Access key best practices & alternatives__ select **Other**. This is just an informative warning page about
the security implications of using access keys.
*** Retrieve your *Access key* and *Secret access key* on one of the next pages and **save them somewhere safe**.
* When you are done with development and testing, delete the Access Key.

=== Note on AWS CLI

AWS CLI (https://aws.amazon.com/cli/) is not directly needed for development and testing purposes.

== Testing

Testing is done using PHP Unit by using the provided link:../phpunit.xml[phpunit.xml] configuration.

Being a bundle, tests are encouraged but not necessarily implemented in this repository. Integration tests are
implemented in a separate vanilla Symfony project and tested there.

To set up integration testing environment:

* create a new Symfony project. Hint: you can use ProjectInit for that.
* create `bundle` directory in your project's root directory (next to `src`)
* copy `src` directory and `composer.json` file from this library and paste it into your Symfony project's `bundle`
directory
* add the following to your Symfony project's `composer.json`:
+
[source,json]
----
{
  "repositories": [
    {
      "type": "path",
      "url": "/usr/src/app/bundle"
    }
  ]
}
----
+
`/usr/src/app` is used the root directory of the project if you are using ProjectInit to set up your Symfony environment
as well. That's the default path in Docker containers of ProjectInit created projects. Replace it with the actual path
in your development environment.
* run: `composer require constup-foss/symfony8-aws-secrets-bundle`. This will try to install the bundle and create a
symlink of your bundle in your `vendor` folder.
* if you encounter any conflicts with the published version of this bundle, try changing the `name` property in bundle's
`composer.json` to something else and installing it with `composer require` with that new name provided.

== Managing deployment assets

This library is a Symfony bundle distributed as a Composer package on Packagist. It contains files and directories that
shouldn't be shipped as assets when running `composer require constup-foss/symfony8-aws-secrets-bundle`. Asset filtering
is done using link:../.gitattributes[.gitattributes].

=== What should be shipped

* source code critical for propper functioning of the library
* documentation, including the main `README`
* license
* `composer.json`

=== Excluded assets

All assets that are not a part of the previous list should not be shipped. This includes, but is not limited to:

* unit tests
* development environment configuration (ex. Docker)
* toolset configuration (ex. PHP Unit, PHP CS Fixer, Rector, ...)
* development and environment management tools (ex. shell scripts)
* `composer.lock`
